
Executes TypeScript code in a sandbox environment.

## The description

Always set `description`: one short line shown to the user while this runs (the code itself is hidden from them by default): what you are doing, in the user's language. 8 words at most, starting lowercase, no final period. E.g. 'weighing the hero image', 'je lance les tests du signup'.

## How to use run_typescript

The `run_typescript` tool executes TypeScript code in a V8 isolate (types are stripped in-process; interfaces, type aliases and enums are supported). It is a replayable orchestration sandbox, not a Node.js runtime.

## How to produce the result (the `main` contract)

- The program is an ASYNC function body: top-level `await` always works.
- The result is the first that applies:
  1. a top-level `return <value>;` - its value wins over everything else;
  2. otherwise, if a `function main` DECLARATION is present, the sandbox calls `main()` automatically and its resolved value is the result;
  3. otherwise the output is "".
- RECOMMENDED: put all your code in `async function main() { /* ... */ }` and `return` the final result from it. Do NOT call `main()` yourself - a top-level call to `main()` plus no top-level `return` makes it run TWICE.
- The `main` detection is textual: only a `function main` DECLARATION is recognized. `const main = async () => ...` is NOT detected - with it the program outputs "" unless it has a top-level `return`.

## Output rules

- The tool output is ONLY the result value (from `main` or a top-level `return`). It is serialized with JSON.stringify (plain strings pass through verbatim).
- console.log/console.error/console.warn do NOT reach the tool output; they are debugging-only. NEVER rely on console.log to return data - always `return` the value.
- The tool output is truncated at 20,000 characters.
- JSON serialization caveats: `undefined` values and fields are silently dropped; `NaN`/`Infinity` become `null`; `BigInt` and circular references make the program fail with "the program ended without returning"; `Map`/`Set` serialize to `{}` and `Date` to an ISO string - convert them explicitly when shape matters (`Array.from(map.entries())`, `date.toISOString()`).

## Returning images

- To show images to the model, return a non-empty ARRAY of content blocks: `{ type: 'text', text }`, `{ type: 'image', data: '<base64>', mimeType: 'image/png' }`, or `{ type: 'image', path: '/abs/file.png' }` (a local PNG/JPEG/GIF/WebP file, e.g. a screenshot taken with `bash`). The blocks replace the result: the images reach the model as images, not as text.
  Example: `await bash('screencapture -x /tmp/s.png'); return self.readImages('/tmp/s.png');`

## Replay model (IMPORTANT)

- The program is re-executed from the beginning on every pending tool call. Recorded tool results are replayed to the program by POSITION (call order), not by name.
- Keep the program deterministic: tool calls must happen in the same order and with the same arguments on every replay. Deriving tool-call arguments from `Math.random()` desyncs the replay (the recorded result answers the round-1 arguments, not the current ones).
- `Date.now()`/`new Date()` are recorded and replayed with stable values across rounds; `Math.random()` is NOT recorded - it returns fresh values on every re-execution.
- Local side-effect-free code therefore runs more than once: keep it to pure orchestration, data transforms, and tool-call wiring.
- Do NOT use `setTimeout`/`setInterval` (they do not exist - see below); use direct awaits.

## What exists in the sandbox

Available: standard JS built-ins (JSON, Math, Date, Promise, Object, Array, Map, Set, RegExp, Error classes, Symbol, Proxy, Reflect, WeakMap/WeakSet/WeakRef, BigInt, typed arrays, Intl, Temporal), async/await, generators, async generators, for-await, spread/destructuring, optional chaining, `encodeURIComponent`/`decodeURIComponent`.
Also available as bare identifiers (no `tools.` prefix needed, dotted paths compose): `tools.<group>.<function>` connector functions, `search_tool_functions`, `bash` (call with the command string as the single argument), `skill` (call with `{ name: "<exact name>" }`), `self.compact`/`self.reload` (ack immediately, run at the end of the turn), `self.sleep` (call with the seconds: `await self.sleep(10)` or `await self.sleep({ seconds: 10 })`; bounds 0 < s < 20; the HOST sleeps once between replay rounds, the result replays by position).
`self.readImages(paths)` (alias `self.readImage`) shows local image files to the model: give one path or an array of paths (absolute, `~/`, or relative to your working directory); it checks each file exists and is a PNG/JPEG/GIF/WebP, and returns the `{ type: 'image', path }` blocks for your `return`. A missing file or another type throws with the reason. It runs locally: no tool call, nothing to replay. Examples: `return self.readImages(['shots/a.png', 'shots/b.png']);`, or with text: `return [{ type: 'text', text: 'before / after' }, ...self.readImages(['before.png', 'after.png'])];`

## What does NOT exist (and the traps)

There is no Node.js, no browser API, no network I/O, no filesystem, no module system. In particular these identifiers DO NOT EXIST and MUST NOT be used: `fetch`, `setTimeout`, `setInterval`, `clearTimeout`, `Buffer`, `process`, `require`, `import`, `crypto`, `performance`, `URL`, `URLSearchParams`, `TextEncoder`, `TextDecoder`, `atob`, `btoa`, `DOMParser`, `structuredClone`.
TRAP: `typeof fetch` still prints "function" because unresolved identifiers fall through a proxy that turns them into tool calls. Calling one produces misleading errors: "unknown tool: fetch", or "bad tool request from the program" (when the argument is a non-serializable value like a function). Treat these error messages as "this API does not exist in the sandbox" - never retry, rewrite the code.

## Error handling

- A tool call that fails does NOT throw: the error string becomes the awaited value. Check results before using them, and use try/catch around local code.
- If `main` throws or rejects, the tool fails with the error message (the model can read it and retry).
- A syntax error in the TypeScript fails the whole call with "SyntaxError: ...".

## Limits

- Each execution round has a 10-second CPU watchdog; the isolate heap is capped (allocation beyond ~64MB kills the process with exit 133).
- The whole program (all replay rounds combined) has a 1000-step budget.
- Inner `run_typescript` calls are not supported ("run_typescript inside a program is not supported").

## Calling tools

- Prefer `Promise.allSettled(...)` for independent calls; `Promise.all(...)` only when all must succeed. Avoid sequential awaits when calls can run concurrently.
- When a string contains double quotes, use single quotes for the outer string.
  WRONG: `await tools.web_search.news_search({ query: ""Sample Topic" TV date" });`
  CORRECT: `await tools.web_search.news_search({ query: '"Sample Topic" TV date' });`
- Discover exact signatures with `search_tool_functions` (mode=best_match, then mode=details) before calling an unfamiliar function.

## Example

```json
{"code": "async function main() {
  const news = await tools.web_search.news_search({ query: 'space launch', limit: 5 });
  const titles = Object.values(news).map((a: any) => a.title).filter((t: string) => t.toLowerCase().includes('nasa'));
  return { count: titles.length, titles };
}"}
```
