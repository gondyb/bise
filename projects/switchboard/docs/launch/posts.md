## 16:05 · Show HN

**title:** `Show HN: bise – one thread per repo, it runs the coding agents for you`
**url:** https://github.com/gvergnaud/bise (HN prefers the repo for open source; bise.dev in the comment)

**first comment (post it right away):**

> hi HN, i'm Gabriel. i build coding agents for a living. bise is my personal side project.
>
> the problem: with four or five Claude Code / Codex sessions open, i became the router between them. which tab had the context, which one was waiting on me, which two were about to edit the same file. i shipped a lot and never got to think.
>
> bise is a terminal app where you talk to one thread per repo. an agent called main splits what you say into jobs and starts agents in the background. a few design choices:
>
> - one thread per repo that never ends. when it gets long, bise compacts it. no sessions to manage.
> - the input is never locked. you can message main or any agent (⌥ + a number, or @name) while they run.
> - agents message each other before they touch the same files. they make a git worktree only when one needs its own copy, and remove it after.
> - agents call tools by writing TypeScript (programmatic tool calling). every MCP server becomes functions, so you can keep a lot of them on without filling the context.
> - decisions that need you go to an inbox above your input, answered with one key. main answers the obvious ones itself and says why.
>
> what isn't done:
>
> - macOS only (Apple silicon and Intel). Linux is next.
> - no approval mode yet. agents run shell commands in your repo without asking. use it on repos you trust and commit often. approvals are the next big thing i build.
> - pre-release. bring your own key (Anthropic, OpenAI, Mistral and more).
>
> most of bise was built with bise. site: https://bise.dev
>
> i'd love to hear where the one-thread model breaks for you, and what broke on install.

left out on purpose: the Bend proofs (the full Lean check has never run; say it only if asked, and say exactly that).
