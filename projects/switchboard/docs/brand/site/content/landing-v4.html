words: repo vs project

you used "project" for two things: the repo, and the pieces of work inside it. on the site, one word for each.

the rule

repo = the folder. one repo, one thread.

work (or "things", when it's casual) = what happens inside it: tasks, fixes, features, the agent that did each one. never "project" or "session".

so the line is: one thread per repo. bise knows everything going on in it.

"project" stays out of the copy. it's the word everyone uses for both, so it's the one that confuses.

one question: the TUI panel still says "0 :* main". if the site says "bise", should the product say "bise" too? i think yes (one name for one thing), but it's a product change, so it's your call and main's.
