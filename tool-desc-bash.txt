Run a real shell command (/bin/sh -c) and return its combined output. Args: the command.

A command that runs longer than the sync window (30 seconds) is not killed: it keeps running as a BACKGROUND process and the tool returns immediately with an id and a file contract (dir, .out output, .in stdin fifo, .pid, .rc exit code). Interact with it using further bash calls: read new output with `tail -n 50 <dir>/<id>.out`, feed stdin with `printf '%s\n' 'text' > <dir>/<id>.in` (only if the command reads stdin), check liveness with `kill -0 $(cat <dir>/<id>.pid)`, get its exit code with `cat <dir>/<id>.rc`, list all background commands with `ls <dir>`, and kill one with `kill $(cat <dir>/<id>.pid)`. Decide yourself whether a long-running command is still worth its slot, and clean up when done.
