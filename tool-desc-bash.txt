Run a real shell command and return its combined output. Args: the command. The command may span multiple lines (scripts, heredocs, if/for blocks run as written). Notes: a process writing more than ~50MB to any file is terminated (exit 153); a background command that reads stdin waits for input until fed via the fifo or killed; temp scripts are deleted after each call.

A command that runs longer than the sync window (30 seconds) is not killed: it keeps running as a BACKGROUND process and the tool returns immediately with a file contract: every line is a ready-to-run command on concrete paths, with the process's real pid already substituted (copy-paste verbatim). Interact with it using further bash calls: read new output with `tail -n 50 <dir>/<id>.out`, feed stdin with `printf '%s\n' 'text' > <dir>/<id>.in` (only if the command reads stdin), check liveness with `kill -0 $(cat <dir>/<id>.pid)`, get its exit code with `cat <dir>/<id>.rc`, list all background commands with `ls <dir>`, and kill one with `kill $(cat <dir>/<id>.pid)`. Decide yourself whether a long-running command is still worth its slot, and clean up when done.
